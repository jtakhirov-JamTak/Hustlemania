## Findings by severity

**P2-1 — Impediment without RECOVERED WHEN is saved, contrary to the F17 e2e line.**
SPEC F17 e2e: "an impediment typed without 'recovered when' → Save refused, the hint reads the RECOVERED WHEN line, the `impediments` count in the DB unchanged". Reproduced: `npx tsx -e` calling `stubParse('impediment', 'When I reach for the phone between tasks, then the phone goes in the drawer.')` → `{"when":"…","then":"…","recovered_when":""}` and `missingPart('impediment', …)` → `null`. In `lib/capture.ts:41-42` the impediment kind marks `then` and `recovered_when` `required: false`; `components/LibraryPage.tsx:92` documents Save gating as "an impediment's WHEN" only. The e2e suite tests the analogous cue/REMIND case instead (`golden-path.spec.ts:661-672`), so this line has no executable coverage. Note the SPEC is internally inconsistent here: F15's editor rule is "WHEN and at least one situation are needed" and rule 6 completes THEN/RECOVERED WHEN in the wizard; the implementation follows F15. The SPEC must settle which rule holds; I am not proposing which.

**P2-2 — The `no_situations` delete refusal names the sprint, not the item.**
SPEC: "a `no_situations` refusal names the item in the error bar" / e2e "the refusal names the impediment". `SituationLibraryPage.tsx:37-44` renders `{area} · "{outcome}": one of its items would be left without a situation.` from `affected_sprints_check`'s failing shape (`0019_situations.sql:584`: `sprint_id, area, outcome, reason` — no item). The e2e asserts only "Delete is blocked" and the reason text (`golden-path.spec.ts:633-634`). The item is visible on the preceding sheet ("Removed from: …"), which softens it.

**P2-3 — Visual evidence gaps.** `docs/mockups/f17-capture/*-impediments-add-failed.png` shows "That entry is too long to sort — 2,000 characters at most" (the `invalid_input` path), not the SPEC'd `PARSE_STUB=fail` "Could not sort it — fill the parts by hand." state. No capture of "the picker's capture". The phone `situations-delete-sheet-history` captures show page content bleeding through the dialog and the nav bar twice — consistent with a full-page screenshot artefact of fixed positioning, not verified in a live browser either way.

**P2-4 — Copy longer than specified.** SPEC: blurb "The situations your cues and impediments apply to." and empty "No situations yet."; `SituationLibraryPage.tsx:19,21` extend both sentences. The SPEC strings are prefixes of what ships; e2e checks `toContainText`.

**Harness note (not a code finding).** The task prompt's documented read-only DB path `docker exec supabase_db_Hustlemania psql …` is blocked (`docker` not on the evaluator allowlist), as is `python` (so `npm run test:hooks` could not be run) and any `2>&1` redirection.
